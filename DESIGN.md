# Joyride visual system

## Direction

The counter run sheet: a calm, legible operations workspace inspired by the daily paper record a rental desk would keep. Active rides and payment states lead; fleet and history follow.

## Surfaces

- Warm off-white workspace with white data surfaces and fine ink rules.
- The earlier Joyride palette is retained by user request: navy navigation, orange primary actions, warm cream canvas, green for ready or paid, blue for rides in progress, and gold for payment due.
- The real toy-car photograph belongs on the sign-in screen. The operational dashboard uses no decorative hero.

## Type and structure

- DM Sans carries headings, controls, and data at fixed UI sizes.
- Headings are direct, without eyebrow labels. Numeric values use tabular figures.
- Desktop has a steady navigation rail. Mobile uses a clear bottom navigation and stacked data.
- Active rentals appear as readable rows with time and resolution actions. The overview metrics read as one horizontal summary surface.

## Interaction

- Buttons and switches use native semantics with visible keyboard focus.
- Hover and pressed states are subtle. Motion communicates state changes only.
- Empty states explain the next useful action.

## Scope

Apply the same grammar to authentication, overview, fleet, history, settings, dialogs, and demo mode without changing rental or Firebase behavior.

The Analysis page extends the grammar with paid-rental totals and a Monday–Sunday chart. Its insight text must come from the chart data. The user defines profit as collected payments until expenses are tracked.

The interface language is Turkish. The weekly chart stays simple; monthly rows for a chosen year and yearly comparison rows provide deeper detail below it.
